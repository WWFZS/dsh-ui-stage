# 设计：输入框透明（玻璃化）

> 目标：应用主题壁纸后，**输入框不再是一块实色板**，壁纸从它底下透出来；
> 但"字永远看得清"这条底线不能破。

**已定（2026-11-24）· 已实施**

- 强度：**跟列底同透** —— α 由"字还看得清"解出来，夹在 **0.35–0.85**（0.35 是项目既有的
  `WALL_ALPHA_MIN`，不是新立的规矩）。
- 范围：**输入框本体 + 框内按钮 + @ 提及菜单**（发送按钮保留强调色实底；用户消息气泡这一版不动）。

**真机实测（改前 → 改后）**

| 项 | 改前 | 改后 |
|---|---|---|
| `--dsw-specific-input-major` | `#0d1524`（不透明） | `rgba(13, 21, 36, 0.4)` |
| 输入卡片 computed bg | `rgb(13, 21, 36)` | `rgba(13, 21, 36, 0.4)` |
| 框内按钮 | 不透明 | `rgba(13, 21, 36, 0.48)` |
| 卡片 `--dsa-card` | `#0b0e15` | 不变（正文仍站在实底上） |

输入框那段 DOM 链实测是：`GRgSLq_input`(透明) → `GRgSLq_grow`(透明) → `GRgSLq_scroll`(透明)
→ **`GRgSLq_card`（就是它上色，radius 28px）** → `GRgSLq_root`(透明)。整条祖先链背后没有
第二块实卡，所以带 α 就能真的透出壁纸 —— 这是"改 token 就够"的前提，已确认。

---

## 1. 要什么 / 不要什么

**要**：输入框（红框那个）能看见背后的壁纸；壁纸越花，输入框越像一块薄玻璃。

**不要**：

- 不要为此新增一根滑杆（界面做减法，主题页已经三根了）。
- 不要让字压在生壁纸上（花壁纸里飘过一块亮区就会吃掉字，这是这个插件最不能出的问题）。
- 不要改 `backdrop-filter` 在**列/面板**上的禁令（那条禁令的理由是"它糊的是列里自己的正文"，
  输入框是叶子节点、背后只有壁纸，不适用）。

---

## 2. 现状：输入框吃的是哪一层

| 层 | 令牌 | 现在 | 说明 |
|---|---|---|---|
| 壁纸层 `.dsa-wall` | — | 满屏 | 不动 |
| 列底 | `--dsw-alias-bg-base` ← `dsa-wall-wall` | `rgba(面, wallAlpha)` | `wallAlpha` 由引擎按可读性求解 |
| 卡片 | `--dsa-card` ← `dsa-wall-card` | 不透明 0.92 | 只在卡片式布局生效 |
| **输入框** | `--dsw-specific-input-major` ← **`dsa-wall-glass-2`** | **不透明 hex**（`g1.final`） | ← 就是这块挡着壁纸 |
| 输入框里的按钮 | `--dsw-alias-button-floating-fill` 等 | 不透明 | 可选一起做 |

关键点：`dsa-wall-glass-2` 与 `-1` / `-3` 目前是**同一个不透明色**（`g1.final`），
所以"玻璃"其实只有颜色没有透明度 —— 这是为什么输入框看起来是块实色板。

---

## 3. 三个方案

### A. 纯透明（`transparent`）

最小改动，但**不建议**：输入区完全失去边界（壁纸同色时找不到输入框），
且字直接压在生壁纸上，深色字遇到暗壁纸=1.2:1。

### B. 恒定半透（固定 α）

`input-major → rgba(玻璃色, α)`，α 取一个常数（0.35 / 0.5）。

- 优点：一个 token 改完，简单、稳定、可预测。
- 缺点：α 是常数，壁纸亮度却会变 —— 亮壁纸要 0.5 才够读，暗壁纸 0.5 又白透一层"灰罩"。
  这正是引擎里 `solveWallAlpha` 存在的理由。

### C. 跟列底同透（**已采用**）

`input-major → rgba(同一个面, max(wallAlpha, 0.18))`

- 输入框不是"新的一层"，而是**和列底同一个面**：同一块玻璃，只是一圈描边把可输入区圈出来。
- `wallAlpha` 本来就是引擎按"字要看得清"反解出来的最小遮挡量，直接复用 → **零新增数学，
  可读性天然达标**；壁纸越亮它越大（自动加深），壁纸越暗它越小（更透）。
- 下限 0.18 是"看得见输入框"的边界传感器：低于它，深色壁纸上输入框直接消失。

**采用 C**，并把 A 的"完全看不见边界"用一圈 1px 描边（`--dsw-alias-border-l1`，已有）补掉。

---

## 4. 推荐档位的具体数值

`α = clamp(solveWallAlpha(玻璃色, 字色, 最坏壁纸块), 0.35, 0.85)`

- 下限 0.35 = `WALL_ALPHA_MIN`（项目既有规矩：再透就不是玻璃而是"没有"）。
- 上限 0.85：永远留一点壁纸色，不做成实色板。
- 解的对象是**玻璃色** `g1.final`，不是壁纸主色 `wallBase` —— 传错对象会拿白釉的解套深釉的面。

参考：白字 `#fff` 要达到 4.5:1，底面亮度必须 ≤ 0.183（约 `#787878`）。
在纯白壁纸上，纯黑面需要 α ≈ 0.52 才达标 —— 所以"近全透"和"字清楚"在亮壁纸上是互斥的，
只能让 `wallAlpha` 决定。深色壁纸上 α 会自然掉到 0.2 左右，看起来就是"几乎全透"。

配套（都是 token 级，不需要选择器手术）：

| 令牌 | 改成 |
|---|---|
| `--dsw-specific-input-major` | `rgba(13, 21, 36, α)` ← `dsa-wall-input` |
| `--dsw-specific-menu` | 同上（@ 菜单与输入框是同一个面） |
| `--dsw-alias-button-floating-fill` | `rgba(面, α + 0.08)` ← `dsa-wall-input-lift`（夹到 ≤ 0.92） |
| `--dsa-card` / `--dsw-alias-bg-base` | **不动**（列底已经是 α 的同族，改了会连带整个界面） |

发送按钮保持强调色实底（它是"动作"，不是"面"）。

---

## 5. 设置页要不要加东西

**不加滑杆、不加开关。** 理由：出厂就该是用户想要的样子；多一个开关等于承认默认值不对。
若以后有人嫌"太透/太实"，再把 α 接到已有的「遮罩厚度」上（遮罩越厚，输入框越实），
那是下一步的事，不进这一版。

---

## 6. 验收标准

1. 输入框区域能明显看到壁纸（截图对比：改前/改后的同一张壁纸）。
2. 输入框里的占位字、已输入文字、按钮图标对比度 ≥ 4.5:1（设置页的读数旁再加一条
   "输入框"实测值 —— 这是给用户看的证据，不是自嗨）。
3. 壁纸换成纯白 / 纯黑两张极端图，输入框都不会"消失"（边界仍可见）。
4. 关掉壁纸 → 输入框回到内核实色，与原生观感一致。
5. 三根滑杆拖动时输入框跟着重算（不卡顿，不闪白）。

---

## 7. 风险与兜底

| 风险 | 兜底 |
|---|---|
| 内核不给输入框描边，纯 α 下边界会糊 | 用 `box-shadow: inset 0 0 0 1px var(--dsw-alias-border-l1)` 的**结构选择器**补（需定位到输入容器） |
| `input-major` 被内核用别的方式（非 background）消费 | 落地前先探测；不行就退回"给容器加背景"的选择器方案 |
| 输入框背后其实是**不透明卡片**（卡片式布局生效时） | 那就只透到卡片色 —— 这时"透"没有意义，必须同时把该列卡片也放透；需先确认卡片规则是否还在生效 |
| 每次 α 变化都重写样式表（拖滑杆时） | 复用现有 `paintCss` 的 lastCss 短路；α 跟随 `wallAlpha`，本来就在重算链里 |

---

## 8. 实施顺序（下一步）

0. **先探测一次**（真机一次，不截图）：列出输入框节点的 computed `background-color`、
   它的祖先链、以及背景是不是壁纸。这一步决定"改 token"够不够。
1. 改 `deriveTokens`：新增 `dsa-wall-input`（rgba + α）与 `dsa-wall-input-solid`（聚焦/兜底用）。
2. 改 `layoutVars`：把 `input-major` / `specific-menu` 接上新 token。
3. 设置页加一行实测读数（可选，若能算准）。
4. 测试：`client-test` 断言 `input-major` 带 alpha 且 α ≥ 0.18；壁纸关闭时回落原值。
